Overview#

Tiers 1 and 2 are the same desert soil study twice, once small enough to read off the screen and once large enough that the penalty has to be chosen rather than guessed. Both were curated for this book. Tier 3 asks the next question: what happens when you point the same two plugins at a table that nobody prepared for a plugin demonstration.

There are two examples here, and they are deliberately unequal. It is worth saying why before you pick one, because the asymmetry is the point rather than an oversight.

Gut-to-soil is the statistically substantive example. It is a real composting time series with a real experimental design, it is a few times wider than it is tall, and every command on its three pages can be run against files that download from the upstream tutorial site right now. It is the only place in this book where the multiple-graphical-lasso machinery has a grouping variable worth using — the samples span two ends of a process that changes the community completely, so “which associations survive that change” is a question with an answer rather than an illustration.

The cocoa appendix ships nothing. It exists to establish one narrow claim: that a shotgun-derived abundance table — Bracken, Kaiju or MAG-level — enters qiime gglasso transform-features and qiime classo transform-features exactly as an ASV table does, because neither plugin knows or cares how the rows were counted. It cannot demonstrate anything beyond that, both because no feature table for the study is published and because 14 samples are far too few to estimate a covariance matrix from. It is an appendix for that reason and not because it was written last.

Important

If you want to do something, go to Gut-to-Soil. Read the cocoa note only if you are planning to bring your own shotgun data and want to know what it has to look like when it arrives.

“Metagenomics” is being used loosely#

Gut-to-soil is 16S amplicon data, not shotgun metagenomics. Calling this tier “metagenomics” is a stretch, and the honest reading of the tier is community profiles that were generated by someone else, for their own reasons.

That looseness turns out not to matter much for the statistics, and it is worth being clear about why. Both plugins take a FeatureTable. Neither inspects provenance, neither knows whether a row is an ASV, a species called by Kraken2 or a dereplicated MAG, and neither behaves differently as a result. What actually changes between an amplicon table and a shotgun table is not the interface:

  • What a feature means. An ASV is a sequence variant, which may or may not correspond to an organism; a MAG is a genome bin. Edges inherit whatever ambiguity the features carry, and no amount of regularization fixes it.

  • Depth and sparsity. Shotgun tables are usually deeper and less zero-heavy at a given taxonomic rank, which makes the log-ratio transform less dependent on how you treat zeros. Shallow amplicon tables — like the one in this tier — make that choice load-bearing.

  • Compositionality, which does not change. Both are relative abundances. Sequencing depth is a property of the run, not of the sample, so the constraint that motivates the log-ratio transform [17] [18] applies identically to both. This is the reason a cocoa Bracken table needs no special handling.

So the modality changes how much you should believe a given edge, not which command produces it.

What tier 3 adds#

No new plugin action. Every q2-gglasso and q2-classo command in this tier has already been demonstrated in Tier 1, and the parameter-selection reasoning comes from Tier 2. Three things are new:

  1. A grouping variable that means something. The composting design splits samples into a gut-derived end and a soil-derived end. That makes the group/fused graphical lasso a scientific question rather than a syntax demonstration — see Network Inference, which also explains why the joint fit currently stops short of running through the QIIME 2 CLI, and what to do instead.

  2. A shallow table. The tutorial subsample is thin enough that the treatment of zeros visibly drives the covariance. This is the normal condition of real 16S data and the tier says so rather than hiding it.

  3. Data you did not curate. Column names, sample types and levels are whatever the upstream study chose. The pages here therefore tell you to read the metadata before running anything, and quote a value back at you only where they say they checked it against the served sample-metadata.tsv.

Warning

Nothing in this tier has been run against QIIME 2 2026.7, because the tier 3 recompute has not been run yet. Every page shows commands and explains what they do; none shows captured output, edge counts, \(R^2\) values or runtimes. Where output would naturally appear, the page says it is pending verification. Treat any number you find elsewhere for this dataset as unconfirmed.

Before you start#

The files are fetched in Download the Tutorial Data, which is the canonical download page for the whole book; the tier 3 section of it works today, unlike tiers 1 and 2, whose Zenodo DOI has not been minted.

The traps you are most likely to hit — --i-taxonomy being required but unused, build-groups not chaining into solve-problem, --p-rank raising, pca needing both a latent solution and a metadata file — are collected in Troubleshooting. None of them is specific to this tier, but this tier is where the second one starts to hurt.
