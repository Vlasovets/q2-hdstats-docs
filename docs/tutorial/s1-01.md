# Compositional data

Compositional data arise when an observation describes the parts of a whole and only the relative magnitudes of the parts are identifiable. The absolute scale of the vector is arbitrary: two positive vectors that differ only by a common multiplicative factor carry the same compositional information {cite:p}`aitchison1982statistical,gloor2017microbiome`. If $u=(u_1,\ldots,u_p)$ is a vector with positive components, the closure operation maps this representative to

```{math}
:label: eq:closure

x = \mathcal{C}(u)
= \left(\frac{u_1}{\sum_{k=1}^{p}u_k},\ldots,
\frac{u_p}{\sum_{k=1}^{p}u_k}\right).
```

The composition $x$ lies in the simplex

```{math}
:label: eq:simplex

\Delta^{p} = \Big\{ x \in \mathbb{R}^{p}_{>0} \; : \; \textstyle\sum_{j=1}^{p} x_j = 1 \Big\}.
```

Since $\mathcal{C}(a u)=\mathcal{C}(u)$ for all $a>0$, the closed vector is a representative of an equivalence class of proportional vectors. Statistical procedures for compositional data should therefore not depend on the arbitrary total used to represent the composition.

Microbiome sequencing count data fit naturally into this framework. Let $X^{\mathrm{c}}=(x^{\mathrm{c}}_{ij})\in\mathbb{N}_0^{n\times p}$ denote the sequencing count matrix returned by high-throughput sequencing and bioinformatic processing, for example with DADA2 {cite:p}`callahan2016dada2`. Let $x^{\mathrm{c}}_{i\cdot}=(x^{\mathrm{c}}_{i1},\ldots,x^{\mathrm{c}}_{ip})$ denote its $i$th row and $x^{\mathrm{c}}_{\cdot j}=(x^{\mathrm{c}}_{1j},\ldots,x^{\mathrm{c}}_{nj})^\top$ its $j$th column. Let the sequencing depth of sample $i$ be the row sum $s_i=\sum_{j=1}^{p}x^{\mathrm{c}}_{ij}$ and the corresponding feature total be $s_{\cdot j}=\sum_{i=1}^{n}x^{\mathrm{c}}_{ij}$. The sample-specific sequencing depth is affected by sample processing, DNA extraction, amplification, library preparation and sequencing depth, and is not by itself an independent measurement of total microbial load {cite:p}`vandeputte2017quantitative,tkacz2018absolute`. The count table therefore carries relative, not absolute, information about the microbial features. A standard first representation is total-sum normalization,

```{math}
:label: eq:total-sum-normalization

x_{ij} = \frac{x^{\mathrm{c}}_{ij}}{s_i},
\qquad
x_i=(x_{i1},\ldots,x_{ip}),
```

which maps each sample to proportions in $\Delta^p$.

In QIIME 2, raw unnormalized counts are represented as a feature table with semantic type `FeatureTable[Frequency]`: each entry is a whole-number frequency or count of a feature in a sample. Its rows are samples and its columns are amplicon sequence variants (ASVs) or other microbial features. Core QIIME 2 can also store total-sum-normalized proportions as `FeatureTable[RelativeFrequency]`, whose feature values sum to one within each sample. The **q2-classo** and **q2-gglasso** `transform-features` actions currently accept `FeatureTable[Frequency]` and `FeatureTable[Composition]` as raw inputs, but do not declare `FeatureTable[RelativeFrequency]` as an input type. Proportion-valued tables therefore need the accepted `FeatureTable[Composition]` type before they can enter these actions.

Microbiome sequencing data also have an inherent hierarchical structure: the features can carry taxonomic labels and be placed as leaves of a taxonomic tree $\mathcal{T}$. In QIIME 2, this information is stored separately as a taxonomy artifact, while outcomes and sample-level covariates are supplied as Metadata. This separation is useful for the two plugin families considered here: the abundance table supplies the composition, taxonomy supports annotation and tree-based aggregation, and Metadata supplies outcomes, groups, or covariates.

Aitchison's formulation of compositional data analysis (CoDA) is based on log-ratios and equivalent logarithmic transformations of compositions {cite:p}`aitchison1982statistical`. The simplest log-ratio compares two positive features $j$ and $k$ in sample $i$,

```{math}
:label: eq:logratio-invariance

\log\left(\frac{x_{ij}}{x_{ik}}\right)
=
\log\left(\frac{x^{\mathrm{c}}_{ij}/s_i}{x^{\mathrm{c}}_{ik}/s_i}\right)
=
\log\left(\frac{x^{\mathrm{c}}_{ij}}{x^{\mathrm{c}}_{ik}}\right),
```

showing that the sample sequencing depth $s_i$ cancels. Hence the same log-ratio is obtained from raw counts and from total-sum-normalized proportions, provided both features are observed.

The centered log-ratio (CLR) transformation was introduced in the same CoDA framework {cite:p}`aitchison1982statistical`. It gives a full $p$-coordinate representation by comparing each part with the within-sample geometric mean. For a strictly positive composition $x_i$,

```{math}
:label: eq:clr

\operatorname{CLR}(x_{ij}) = \log\left(\frac{x_{ij}}{g(x_i)}\right),
\qquad
g(x_i)=\left(\prod_{k=1}^{p} x_{ik}\right)^{1/p},
```

where $g(\cdot)$ denotes the geometric mean. The CLR coordinates sum to zero within each sample and are invariant to multiplication of the original count vector by a sample-specific positive constant.

Both pairwise log-ratios and the CLR require positive components. Zeros are common in microbiome feature tables, so a practical CLR analysis must either add or replace zeros with a small positive value before taking logs. This choice changes the geometry of sparse tables and therefore becomes part of the statistical model. The plugin interfaces expose this zero floor as `--p-coef` in **q2-classo** and as `--p-pseudo-count` in **q2-gglasso**.

**Example:**

```bash
# q2-classo: replace zeros by coef, then apply CLR
qiime classo transform-features \
    --i-features counts.qza \
    --o-x Z-classo-clr.qza

# q2-gglasso: add a pseudo-count, then apply CLR
qiime gglasso transform-features \
    --i-table counts.qza \
    --i-taxonomy taxonomy.qza \
    --o-transformed-table Z-gglasso-clr.qza
```

The modified CLR (mCLR) of {cite:t}`yoon2019microbial`, available in **q2-gglasso**, avoids pseudo-counting zeros by transforming only the observed positive components and leaving zeros at zero. Let $J_i=\{j:x_{ij}>0\}$ denote the non-zero features in sample $i$ and

```{math}
:label: eq:positive-geometric-mean

\widetilde{g}(x_i) =
\left(\prod_{j \in J_i} x_{ij}\right)^{1/|J_i|}.
```

Following {cite:t}`yoon2019microbial`, the shifted mCLR is

```{math}
:label: eq:mclr

\operatorname{mCLR}_{\epsilon}(x_{ij}) =
\begin{cases}
0, & x_{ij}=0,\\[4pt]
\log\left(\dfrac{x_{ij}}{\widetilde{g}(x_i)}\right)+\epsilon,
& x_{ij}>0,
\end{cases}
\qquad
\epsilon = |z_{\min}| + c,\quad c>0,
```

where

```{math}
:label: eq:mclr-shift

z_{\min} =
\min_{i,j:x_{ij}>0}
\log\left(\frac{x_{ij}}{\widetilde{g}(x_i)}\right).
```

The constant shift preserves the ranks among non-zero entries while making every non-zero transformed value larger than the zero entries. The original SPRING implementation uses $c=1$; the current **q2-gglasso** implementation fixes $c=0.1$ and does not expose it as a command-line parameter.

**Example:**

```bash
# q2-gglasso implements mCLR directly
qiime gglasso transform-features \
    --i-table counts.qza \
    --i-taxonomy taxonomy.qza \
    --p-transformation mclr \
    --o-transformed-table Z-mclr.qza

# q2-classo can use the resulting transformed table as its design
qiime classo regress \
    --i-features Z-mclr.qza \
    --m-y-file metadata.tsv \
    --m-y-column y \
    --o-result fit-regression.qza
```

Let $T$ denote the chosen transformation, such as CLR or mCLR, and let $Z=(z_{ij})\in\mathbb{R}^{n\times p}$ denote the resulting transformed table. This transformed table is the starting point for the regression, classification, and graphical-model formulations below.
