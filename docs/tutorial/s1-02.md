(sec:logcontrast)=
# Generalized log-contrast regression and classification with **q2-classo**

The statistical object of interest is the sparse log-contrast model for compositional covariates. Let $X=(x_{ij})\in\mathbb{R}_+^{n\times p}$ be a positive compositional data matrix, with row $x_i=(x_{i1},\ldots,x_{ip})$, and let $\log(X)$ denote the entrywise logarithm. After centering the response, or equivalently after adding an unconstrained intercept, the linear log-contrast model of {cite:t}`aitchison1984log` can be written as

```{math}
:label: eq:forward

y = \log(X)\beta+ \sigma\varepsilon,
\qquad
\text{subject to}
\qquad
\mathbf{1}_p^\top\beta= \sum_{j=1}^{p}\beta_j = 0 .
```

Here $y\in\mathbb{R}^n$ is a continuous response, $\beta=(\beta_1,\ldots,\beta_p)^\top$, $\sigma>0$, and $\varepsilon\in\mathbb{R}^n$. The same log-contrast predictor can be generalized to binary classification labels, as described below. The zero-sum constraint is what makes the linear predictor depend on ratios, rather than on an arbitrary total scale of the composition. Indeed,

```{math}
:label: eq:logcontrast-predictor

\eta_i
= \sum_{j=1}^{p}\beta_j \log x_{ij}
= \sum_{j=1}^{p-1}\beta_j
\log\left(\frac{x_{ij}}{x_{ip}}\right),
```

where the last equality follows from $\beta_p=-\sum_{j=1}^{p-1}\beta_j$. Equation {eq}`eq:logcontrast-predictor` uses one reference part only for notation. In the unpenalized case, the model is therefore an ordinary linear model in log-ratio coordinates: the response is modeled as a linear combination of log-ratios, plus noise. The same log-contrast can also be expressed in the overcomplete set of $\binom{p}{2}=p(p-1)/2$ pairwise log-ratios,

```{math}

\eta_i =
\sum_{1\le j<k\le p}
\theta_{jk}\log\left(\frac{x_{ij}}{x_{ik}}\right),
\qquad
\beta_j =
\sum_{k>j}\theta_{jk} - \sum_{k<j}\theta_{kj}.
```

Thus the zero-sum formulation is a compact way to fit a log-ratio prediction without explicitly expanding the design to all pairwise ratios {cite:p}`bates2019log`. For CLR-transformed tables, the same expression is obtained because CLR coordinates differ from $\log x_i$ only by an additive sample-specific constant, which is annihilated by the zero-sum constraint.

In the high-dimensional setting where $p>n$, the log-contrast coefficients are regularized to select a small subset of compositional parts. This is the common setting in microbiome applications, where the number of microbial features typically exceeds the number of samples. For regression, Lin et al. {cite:yearpar}`lin2014variable` proposed the sparse log-contrast estimator

```{math}
:label: eq:sparse-logcontrast

\widehat{\beta}_{\lambda}
\in \operatorname*{arg\,min}_{\beta\in\mathbb{R}^p}
\left\{
\frac{1}{2n}\left\|y-\log(X)\beta\right\|_2^2
+ \lambda\|\beta\|_1
\right\}
\qquad \text{subject to} \qquad \mathbf{1}_p^\top\beta=0 ,
```

with tuning parameter $\lambda\ge 0$. The $\ell_1$ penalty induces sparsity in the log-contrast coefficients and therefore performs variable selection on the compositional parts. The zero-sum constraint gives the estimator its compositional invariance properties, including invariance to a sample-wise multiplicative rescaling of the underlying counts. **q2-classo** uses the more general **c-lasso** constrained sparse estimation framework {cite:p}`Simpson2021` for this log-contrast instance. The package itself is more general: it accepts arbitrary linear equality constraints and exposes robust, scale-estimating, and classification variants of the same constrained estimator. Algorithmically, **c-lasso** exploits the piecewise linear regularized solution paths characterized by {cite:t}`rosset2007piecewise`. Its path-following algorithm is the standard solver whenever this structure is available, while proximal splitting methods such as Douglas--Rachford and primal--dual schemes are also available for formulations or fixed-penalty problems where they are preferable.

Beyond the sparse least-squares estimator, more general log-contrast prediction models have been developed to accommodate robust losses and unknown noise scales. **q2-classo** inherits these formulations from the **c-lasso** package, including robust and concomitant regression extensions {cite:p}`combettes2020perspective,combettes2021regression,mishra2022robust`. The construction of the design $W$, coefficient vector $\theta$, and constraint matrix $C$ is model-specific. In general, let $W\in\mathbb{R}^{n\times d}$ be a design passed to the solver, let $\theta\in\mathbb{R}^d$ be its coefficient vector, and let $C$ be a compatible linear equality-constraint matrix. The general constrained form is

```{math}
:label: eq:general

\min_{\theta \in \mathbb{R}^{d},\, \sigma \in \mathbb{R}_{>0}}\;
f(W\theta - y,\, \sigma) \; + \; \lambda \lVert \theta \rVert_{1}
\qquad \text{subject to} \qquad C\theta = 0 .
```

The symbol $f$ in {eq}`eq:general` denotes the data-fit criterion.

(regression)=
## Regression

In **q2-classo**, four regression formulations are available that differ in the choice of the data-fitting/loss function and in whether the scale $\sigma$ is estimated. Let $r = W\theta - y \in \mathbb{R}^{n}$ denote the residual vector. The Huber criterion with threshold $\rho > 0$ is

```{math}
:label: eq:huber

h_{\rho}(r) = \sum_{i=1}^{n} \ell_{\rho}(r_i),
\qquad
\ell_{\rho}(u) =
\begin{cases}
u^{2}, & |u| \le \rho, \\[2pt]
2\rho\,|u| - \rho^{2}, & |u| > \rho,
\end{cases}
```

so the criterion is quadratic near zero and linear in the tails. As $\rho \to \infty$, $h_{\rho}(r)$ reduces to $\lVert r \rVert_{2}^{2}$, and the Huber formulations reduce to their least-squares counterparts. In {eq}`eq:general`, the corresponding choices of $f$ are

```{math}
:label: eq:fit-criteria

\begin{aligned}
f_{\mathrm{R1}}(r) &= \lVert r \rVert_{2}^{2}, &
f_{\mathrm{R2}}(r) &= h_{\rho}(r), \nonumber\\
f_{\mathrm{R3}}(r,\sigma) &=
\frac{\lVert r \rVert_{2}^{2}}{\sigma} + \frac{n}{2}\sigma, &
f_{\mathrm{R4}}(r,\sigma) &=
h_{\rho}\!\left(\frac{r}{\sigma}\right)\sigma + n\sigma .

\end{aligned}
```

Substituting these criteria gives the four regression estimators

```{math}
:label: eq:R1

\begin{aligned}\text{R1, least squares:}\quad
&\min_{\theta}\; \lVert r \rVert_{2}^{2} + \lambda\lVert\theta\rVert_{1},
\end{aligned}
```





```{math}
:label: eq:R2

\begin{aligned}
\text{R2, Huber:}\quad
&\min_{\theta}\; h_{\rho}(r) + \lambda\lVert\theta\rVert_{1},
\end{aligned}
```





```{math}
:label: eq:R3

\begin{aligned}
\text{R3, concomitant least squares:}\quad
&\min_{\theta,\sigma>0}\;
\frac{\lVert r \rVert_{2}^{2}}{\sigma} + \frac{n}{2}\sigma
+ \lambda\lVert\theta\rVert_{1},
\end{aligned}
```





```{math}
:label: eq:R4

\begin{aligned}
\text{R4, concomitant Huber:}\quad
&\min_{\theta,\sigma>0}\;
h_{\rho}\!\left(\frac{r}{\sigma}\right)\sigma + n\sigma
+ \lambda\lVert\theta\rVert_{1},
\end{aligned}
```

each subject to $C\theta = 0$, and each with $\sigma$ eliminated (R1, R2) or estimated jointly (R3, R4). Thus the concrete constructions below specify the objects in the general problem {eq}`eq:general` and thereby in the R1--R4 objectives {eq}`eq:R1`--{eq}`eq:R4`. For the original leaf-level log-contrast model in {eq}`eq:forward`, $W=\log(X)$, $\theta=\beta$, and $C=\mathbf{1}_p^\top$. In implementation, a CLR-transformed table $Z$ gives the same predictor, so the corresponding input to the solver is $W=Z$.

R3 and R4 estimate the noise level $\sigma$ jointly with $\beta$. The constants $n/2$ in {eq}`eq:R3` and $n$ in {eq}`eq:R4` arise from the perspective function of the corresponding criterion {cite:p}`combettes2018perspective,combettes2020perspective`. For Huber regression in **q2-classo**, the default threshold is $\rho=1.345$.

In **q2-classo**, the default regression call uses R3, the concomitant least-squares formulation. The boolean options `--p-concomitant` and `--p-huber` select among R1--R4.

```bash
# R3: concomitant least squares (default)
qiime classo regress \
    --i-features Z-classo-clr.qza \
    --m-y-file metadata.tsv --m-y-column y \
    --o-result fit.qza

# R1: least squares
qiime classo regress ... --p-no-concomitant --p-no-huber

# R2: Huber
qiime classo regress ... --p-no-concomitant --p-huber

# R4: concomitant Huber
qiime classo regress ... --p-concomitant --p-huber
```

(sec:classification)=
## Classification

For a binary outcome $y \in \{-1,+1\}^{n}$, the constrained score $W_i^{\top}\theta$ defines a linear classifier through the sign of the fitted margin. Following the regularized path framework of {cite:t}`rosset2007piecewise`, classification can be written with a convex loss that is quadratic on intervals and has a piecewise linear derivative. Combined with an $\ell_1$ penalty, this structure exposes a piecewise linear solution path in $\lambda$ and can therefore be solved efficiently by path-following algorithms. Let $m_i=y_i W_i^{\top}\theta$ denote the signed margin, where $W_i^{\top}$ is row $i$ of the fitted design. Both classification formulations solve

```{math}
:label: eq:hinge

\min_{\theta \in \mathbb{R}^{d}} \;
\sum_{i=1}^{n}\ell^{\mathrm{C}}(m_i)
\; + \; \lambda \lVert \theta \rVert_{1}
\qquad \text{subject to} \qquad C\theta = 0 ,
```

where $\ell^{\mathrm{C}}$ is one of the two loss functions below. There is no concomitant scale parameter. The default C1 criterion in **q2-classo** uses the squared-hinge loss

```{math}

\ell^{\mathrm{C1}}(m)=\frac{1}{2}\bigl[\max(0,1-m)\bigr]^2.
```

Setting `--p-huber` selects C2, which uses the Huberized-hinge loss with $\rho<1$:

```{math}
:label: eq:huber-hinge

\ell^{\mathrm{C2}}_\rho(m_i) =
\begin{cases}
0, & m_i > 1,\\[2pt]
\frac{1}{2}(m_i-1)^2, & \rho \le m_i \le 1,\\[2pt]
(\rho-1)(m_i-\rho)+\frac{1}{2}(\rho-1)^2, & m_i < \rho,
\end{cases}
```

The C2 objective is {eq}`eq:hinge` with $\ell^{\mathrm{C}}=\ell^{\mathrm{C2}}_\rho$. Thus C2 is quadratic near the hinge and linear for sufficiently negative margins. Its threshold is the classification parameter `--p-rho`, whose plugin default is $0.0$; it is unrelated to the residual Huber threshold used in R2 and R4.

```bash
# binary classification
qiime classo classify \
    --i-features Z-classo-clr.qza \
    --m-y-file metadata.tsv --m-y-column y \
    --o-result fit-class.qza

# C2: Huberized-hinge classification
qiime classo classify \
    --i-features Z-classo-clr.qza \
    --m-y-file metadata.tsv --m-y-column y \
    --p-huber --p-rho 0 \
    --o-result fit-class-c2.qza
```

(sec:trac)=
## Tree-aggregated models (`trac`)

When taxonomic tree information is available, the leaf-level microbial features form sparse ASV or OTU counts embedded in a hierarchy whose internal nodes define biologically meaningful subcompositions. A common preprocessing strategy is to remove rare features or to aggregate all features to a fixed taxonomic rank, but this makes the aggregation level a user-defined preprocessing choice rather than part of the statistical model. The `trac` framework of {cite:t}`bien2021tree`, short for tree-aggregation of compositional data, instead learns data-adaptive aggregation levels on the tree and associates the resulting microbial subcompositions with the response.

Mathematically, `trac` reparameterizes the log-contrast problem on the taxonomic tree. Let $\mathcal{T}$ denote the taxonomic tree, and let $A \in \{0,1\}^{p \times t}$ be its binary ancestor matrix, whose column $u$ marks the leaves descending from one of the $t$ retained non-root nodes. Let $m_u=\sum_{j=1}^{p}A_{ju}$ be the number of leaves below node $u$. The tree-aggregated design averages the transformed leaf coordinates,

```{math}
:label: eq:trac-design

W_{iu}=\frac{1}{m_u}\sum_{j=1}^{p}Z_{ij}A_{ju}.
```

When $Z$ is the CLR of a positive table, $W_{iu}$ is the logarithm of the geometric mean of the parts below node $u$, minus the sample-wide mean of the log parts. The latter term cancels in the linear predictor because the node coefficients $\theta=\alpha\in\mathbb{R}^t$ sum to zero. With node weights $w_u=1/m_u$, `trac` solves

```{math}
:label: eq:trac

\min_{\alpha \in \mathbb{R}^{t}}\;
f\!\left(W\alpha - y\right)
+ \lambda \lVert w \odot \alpha \rVert_{1}
\qquad \text{subject to} \qquad \mathbf{1}_{t}^{\top}\alpha = 0 ,
```

which is the tree-specific instance of {eq}`eq:general`. Here $\odot$ denotes the elementwise product. Equation {eq}`eq:trac-design` is the log-geometric-mean construction of {cite:t}`bien2021tree`; the weights $w_u=m_u^{-1}$ correspond to its default aggregation exponent $a=1$. $A$ is constructed internally, and the resulting design $W$ and weights $w$ are passed to the fit. This tree-aggregated formulation is available in **q2-classo**. The `add-taxa` action constructs the corresponding aggregated design and node weights, which are then passed to the `regress` or `classify` actions.

**Example:**

```bash
qiime classo add-taxa \
    --i-features Z-classo-clr.qza \
    --i-taxa taxonomy.qza \
    --o-x design-trac.qza --o-aweights weights-trac.qza

qiime classo regress \
    --i-features design-trac.qza --i-weights weights-trac.qza \
    --m-y-file metadata.tsv --m-y-column y \
    --o-result fit-trac.qza
```

(joint-regression-with-non-compositional-covariates)=
## Joint regression with non-compositional covariates

When additional non-compositional covariates are available for the regression or classification task, they can be added as potential predictors alongside the microbial compositions. These covariates may encode sample metadata, technical factors, or clinical and environmental variables. They are ordinary predictors: their coefficients are not log-contrast coefficients and therefore must not be included in the zero-sum constraint that gives the microbial block its compositional interpretation.

For the leaf-level construction, let $W=Z\in\mathbb{R}^{n\times p}$ and $\theta=\beta$. Let $U\in\mathbb{R}^{n\times q}$ denote the matrix of appended covariates, with coefficients $\gamma_{\mathrm{cov}}\in\mathbb{R}^q$. The augmented design and coefficient vector are $[W\;U]$ and $(\theta^\top,\gamma_{\mathrm{cov}}^\top)^\top$, respectively, so the linear predictor is $W\theta+U\gamma_{\mathrm{cov}}$. The corresponding constraint matrix is

```{math}

\widetilde C = \begin{bmatrix} C & 0 \end{bmatrix},
```

so that the covariate coefficients remain unconstrained. In **q2-classo**, the `add-covariates` action constructs this augmented design and the updated constraint matrix before the model is fitted; the resulting construction is used in the regression objective {eq}`eq:general` or the classification criterion in {eq}`eq:hinge`. Numeric covariates can optionally be rescaled, categorical covariates are expanded into binary indicators, and the new columns carry their own penalty weights (Table {ref}`S1 <tab:params-classo>`). Rescaling is important whenever a covariate measured on a large numeric scale would otherwise dominate a scalar $\ell_1$ penalty applied to log-contrast design columns. A concrete training-set scaling strategy for appended environmental covariates is shown in the high-dimensional Atacama regression example in Section {ref}`S2.2 <sec:highdim-regression>`: the microbial CLR columns are left unchanged, each appended covariate is centered and scaled to the median training-set column length of the ASV block, and the resulting ASV and covariate columns use the same penalty weight.

**Example:**

```bash
# adding covariates
qiime classo add-covariates \
    --i-features Z-classo-clr.qza \
    --m-covariates-file metadata.tsv \
    --p-to-add ph elevation \
    --o-new-features design-cov.qza --o-new-c C-cov.qza \
    --o-new-w weights-cov.qza

# solving regression
qiime classo regress \
    --i-features design-cov.qza --i-c C-cov.qza \
    --i-weights weights-cov.qza \
    --m-y-file metadata.tsv --m-y-column y \
    --o-result fit-cov.qza
```

(sec:classo-model-selection)=
## Model selection

The estimators above are penalized estimators. Their statistical use therefore requires a choice of sparsity level: too much penalization removes genuine signal, whereas too little penalization admits unstable features and over-fitting. In the log-contrast formulations implemented in **q2-classo**, this sparsity level is controlled by the $\ell_1$ penalty $\lambda$. Larger values shrink more coefficients to zero, whereas smaller values allow a larger active set. **q2-classo** fits models along a decreasing path $\mathcal{L}_{\lambda}=\{\lambda^{(1)},\ldots,\lambda^{(M)}\}$ and selects a point on that path using either cross-validation or stability selection.

For $K_{\mathrm{CV}}$-fold cross-validation, let $\mathcal{I}_1,\ldots,\mathcal{I}_{K_{\mathrm{CV}}}$ be a partition of the sample indices $\{1,\ldots,n\}$ and let $\widehat{\beta}^{(-k)}(\lambda)$ be the estimate fit without fold $\mathcal{I}_k$. The cross-validation score is

```{math}
:label: eq:classo-cv

\operatorname{CV}(\lambda) =
\frac{1}{K_{\mathrm{CV}}}\sum_{k=1}^{K_{\mathrm{CV}}}
\frac{1}{|\mathcal{I}_k|}
\sum_{i\in\mathcal{I}_k}
\mathcal{L}\!\left(y_i, \widehat{\eta}^{(-k)}_i(\lambda)\right),
```

where $\widehat{\eta}^{(-k)}_i(\lambda)$ is the out-of-fold linear predictor from the fitted design and $\mathcal{L}$ is the prediction loss appropriate to the chosen regression or classification formulation. The selected penalty is either the minimizer of {eq}`eq:classo-cv` or, under the one-standard-error (1SE) rule, the largest penalty whose cross-validation score is within one estimated standard error of the minimum. The latter rule favors the sparser model among statistically similar candidates and is the default in **q2-classo**; the minimum-CV choice can be requested with `--p-no-cv-one-se`.

Stability selection {cite:p}`meinshausen2010stability` targets variable selection rather than prediction error. Let $\mathcal{B}_1,\ldots,\mathcal{B}_B$ be subsamples of $\{1,\ldots,n\}$ and let $\widehat{A}^{(b)}(\lambda)$ be the active set from subsample $b$,

```{math}
:label: eq:classo-active-set

\widehat{A}^{(b)}(\lambda)=
\{j:\widehat{\beta}^{(b)}_j(\lambda)\ne 0\}.
```

The empirical selection probability of feature $j$ is

```{math}
:label: eq:classo-stability

\widehat{\pi}_j(\lambda) =
\frac{1}{B}\sum_{b=1}^{B}
\mathbb{1}\!\left\{j\in\widehat{A}^{(b)}(\lambda)\right\}.
```

**q2-classo** can visualize these stability-selection probabilities. The resulting display gives an empirical sense of how consistently each coefficient is included under subsampling and therefore how much confidence to place in coefficient inclusion, without turning the selected coefficients into formal post-selection tests. Features with $\max_{\lambda\in\mathcal{L}_{\lambda}}\widehat{\pi}_j(\lambda)$ above a chosen threshold are retained. By default, **q2-classo** then refits the selected support on the full data without the $\ell_1$ penalty. The `--p-no-refit` option instead retains the penalized coefficient vector at the selected penalty. Refitting can reduce shrinkage bias, but its prediction benefit depends on the selected design and task {cite:p}`lederer2013trust`. In **q2-classo**, `--p-cv` enables cross-validation and `--p-stabsel` enables stability selection; the selected $\lambda$, selection rule, refit choice, and any stability threshold should be reported with the fitted model.

(sec:classo-inference)=
## Inference

The fitted **q2-classo** models should be interpreted as sparse prediction and selection models. Classical confidence intervals and $p$-values for individual coefficients are not available in **q2-classo**. After a penalized estimator has selected a model, inference for the selected coefficients requires a post-selection or high-dimensional inference scheme that accounts for the data-dependent selection step. Standard approaches include covariance tests along the lasso path, selective inference conditional on the selection event, and de-biased or desparsified lasso estimators {cite:p}`lockhart2014significance,lee2016exact,javanmard2014confidence,zhang2014confidence,vandegeer2014asymptotically`.

For compositional covariates, these ideas must also respect the log-contrast constraint. {cite:t}`shi2016regression` proposed a de-biased estimator for constrained compositional regression, adapting the Javanmard--Montanari style construction to the orthogonal complement of the constraint space. This provides a route to asymptotic confidence intervals and $p$-values for log-contrast coefficients in that setting. Such inference is not currently implemented in **q2-classo**, and the robust, concomitant, classification, and tree-aggregated formulations considered above would require additional methodological and software work before coefficient-level inferential statements could be reported from the plugin.

(sec:classo-complexity)=
## Computational complexity

The cost of the **c-lasso** path algorithm depends on the number of changes in the active set, as well as on the size of that set. For a dense design $W\in\mathbb{R}^{n\times d}$, forming the Gram matrix for the least-squares path requires $O(nd^2)$ operations and $O(d^2)$ storage. Let $a$ denote the number of active coefficients and $r$ the rank of the active equality constraints. At a path breakpoint, the current implementation inverts an active system of size $a+r$, with a dense cost of $O((a+r)^3)$, and evaluates candidate coefficient changes using the Gram matrix in $O(d(a+r))$ operations. For Huber and classification losses, changes in the loss-active observations can also require the Gram matrix to be recomputed. These costs describe one path step, not the complete path.

Following a piecewise linear path is useful when many penalty values are needed. Numerical comparisons for constrained lasso problems found the path algorithm particularly efficient in this setting {cite:p}`gaines2018algorithms`, and the **c-lasso** scaling experiment compared it with splitting methods and a general convex solver across increasing $n$ and $d$ {cite:p}`Simpson2021`. The number of breakpoints is nevertheless data-dependent. For the ordinary lasso, it can grow exponentially with $d$ in the worst case {cite:p}`mairal2012complexity`. As the selected model becomes dense, the active-system inversion approaches cubic cost in $d$, and the path can become slow. Cross-validation and stability selection require additional fits on folds or subsamples. Within QIIME 2, artifact conversion and provenance recording add overhead to the underlying numerical computation, especially for small fits.
