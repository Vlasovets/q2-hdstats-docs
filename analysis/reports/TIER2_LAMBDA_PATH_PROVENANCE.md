# Tier-2 λ path — provenance and reproducibility

Moved out of `docs/chapters/04_highdim_atacama/02_model_selection.md` on
2026-08-06. Both notes below were sitting mid-chapter, between a reader's command
and its result. They are maintainer concerns — how the numbers were produced and
how closely a re-run matches — and they were undercutting reader confidence at
exactly the point where the chapter asks for it. Nothing here is retracted; it is
relocated.

## The committed table is a re-expression, not the raw output

`analysis/slurm/01_lambda_path.sh` writes
`analysis/results/tables/lambda-path.tsv` with columns
`lambda1 / sparsity / ebic`, straight out of the solution artifact.
`docs/_data/atacama-lambda-path.tsv` is that file re-expressed as
`lambda / eBIC (gamma=0.3) / edges`, with the edge counts derived from the
reported sparsity as $\text{density} \times \binom{300}{2}$.

**That conversion is a hand step, so the two can drift.** They did: the chapter
prose once said 1403 edges at λ=0.3 where the pipeline said 1405. Check both
against `results/tables/lambda-path.tsv` after any re-run rather than trusting
them to stay in step.

Since 2026-08-06 the chapter's figures are generated by
`analysis/scripts/make_docs_figures.py` directly from
`results/tables/lambda-path.tsv`, and that script **asserts** the eBIC minimum is
at λ = 0.8 before writing anything. A re-run that moves the selection now fails
loudly instead of producing a figure that contradicts the prose. The remaining
hand step is the committed TSV, not the figure.

## Reproducibility across the path

The CLI run reproduces the original reference analysis exactly at 11 of the 14
non-empty grid points — including the whole sparse end and, critically, the
selected λ = 0.8 at 216 edges. Three points at the dense end differ by one or two
edges:

| λ | this run | reference |
|---|---|---|
| 0.55 | 819 | 820 |
| 0.35 | 1350 | 1348 |
| 0.30 | 1405 | 1403 |

Two things could produce a difference that small in the dense regime, and the
path artifact does not retain enough information to separate them: genuine solver
variation where many entries sit near the sparsity threshold, or rounding in the
edge counts, which are derived from the reported density rather than counted from
each grid point's precision matrix.

Neither affects the selection. The eBIC minimum is at λ = 0.8 either way, and
agrees with the reference to eight significant figures (16130.0988 vs
16130.099454).

## A caveat the chapter now states openly

Worth recording because it was implicit before and is easy to lose: the eBIC
minimum is **shallow**. λ = 0.8 scores 16130.1; λ = 0.3 scores 16165.1. A
difference of 35 on a scale of ~16,000 separates a 216-edge network from a
1405-edge one. This is the same fact as the γ sensitivity
(γ ∈ [0.30, 0.31] → λ = 0.8; γ ≤ 0.29 → λ = 0.3; γ ≥ 0.32 → the empty network),
seen from the other side.

The old figure hid this — it plotted *eBIC minus each curve's own minimum*, so
every curve bottomed at zero and the depth of the minimum was unreadable. The
replacement plots eBIC on its natural scale, which makes the shallowness visible.
That is a feature: the selected model should not be quoted as though the data
insisted on it.
