1. **`08_summarize.md`, lines 182–190 (the `{important}` block) — the "easy to get a single fit by accident" claim is false, and the specific example is backwards.** `get_hyperparameters` (`/home/itg/oleg.vlasovets/slr_example/q2-gglasso/q2_gglasso/utils.py:302,314–316`) calls `get_range(lambda2_min, lambda2_max, n_lambda2)`, which returns `np.array([None])` when both bounds are unset, and the next branch replaces that with `np.logspace(-1, -4, 5)` — **five** values. So whenever `--p-lambda2-min/--p-lambda2-max` are omitted (every Tier-1 gglasso chapter), `lambda2.size == 5`, the `lambda1.size == 1 and lambda2.size == 1 and mu1.size == 1` test at utils.py:323 fails, and `model_selection` is `True` no matter what `n_lambda1`/`n_mu1` are. The sentence "a forgotten `--p-n-lambda1` gives you a single fit even though you passed a range" is therefore wrong: you still get a (1-point-λ₁) model-selection run with a populated statistics tab. **Fix:** state that a single fit requires pinning `lambda1`, `lambda2` *and* (if latent) `mu1` each to one value, and that leaving `lambda2` unset does **not** count as one value — it silently expands to a 5-point default grid (with the warning `Default values for lambda2 have been used.`). The realistic accident is the opposite one: getting a path when you wanted a single fit. This also makes the surrounding "reduced statistics tab" section rare rather than common, and it contradicts `../90_reference/04_troubleshooting.md:105–114`, which has the same error and should be corrected together.

6. **`08_summarize.md`, lines 95–99 — the `--p-n-cov 0` code path is described with the wrong slice.** With `n_cov=0`, `_clust_data`/`_solution_plot` compute `data.iloc[:-0, :-0]`, and since Python treats `-0` as `0` this makes the **leading ASV block empty**, while the trailing covariate block `data.iloc[-0:, -0:]` becomes the **entire matrix** — the opposite of "the trailing-block slice it produces is empty". The stated consequence (clustering has nothing to work on, via `_get_order` on an empty frame) is right; the mechanism is inverted. **Fix:** "…because `-0 == 0`, the ASV slice `iloc[:-0, :-0]` comes out empty while the covariate slice `iloc[-0:, -0:]` swallows the whole matrix, and the clustering step is handed an empty frame."
