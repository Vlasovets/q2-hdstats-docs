**[R1] gglasso-runtime-1, as a defect in `utils.py:200-224`** — refuted: no regression, and the new guard is not claimed to catch this case.
- The old code was `p, n = counts.shape; depth = counts.sum(axis=0) if p >= n else counts.sum(axis=1)`, evaluated on the same samples×features frame the caller passes. On the documented Atacama input (54 samples × 300 features) `p=54 < n=300`, so the old code took `sum(axis=1)` — the identical axis the new code always takes. Verified numerically: old and new produce the same per-sample series on a 54×300 frame. The noise-amplification behaviour on the clr table is therefore bit-identical before and after this change set; nothing that worked was broken.
- Where the two differ is the 13-feature × 50-sample tutorial shape, where the old code returned 13 per-FEATURE sums indexed `F10, …` (verified) that `md.join(depth)` turned into all-NaN colours. The rewrite fixes that, and `tests/test_seq_depth.py` covers it.
